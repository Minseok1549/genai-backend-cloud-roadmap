B 선택이 필요한 것 — 5건

코드 버그가 아니라 운영 방침입니다. 제가 임의로 정하면 비용이나 서비스 성격이 바뀌기 때문에 판단을 남겨둔 것들입니다. 급한 순서로 놓았습니다.

결정 1 · 배당률 API 쿼터가 트래픽에 열려 있음

가장 급함
현황
배당률은 무료 월 500회가 전부이고 대체 소스가 없습니다. /predict는 인증 없이 누구나 호출할 수 있고(allUsers), 호출될 때 캐시가 만료됐으면 API를 부릅니다. 캐시는 컨테이너 안에만 있어서 인스턴스가 새로 뜨면 사라집니다.
산수
인스턴스 1개 = 6시간마다 1회 → 최대 3개 상시 가동 시 하루 12회 (월 360회) + 일별 배치 월 30회 = 월 390회 / 500회 여기에 콜드스타트마다 1회가 더 붙는다 — 하루 50번 깨어나면 그것만으로 월 1,500회
리스크
쿼터가 소진되면 예외가 나는 대신 폼 모델로 조용히 내려갑니다. 즉 장애로 안 보이고 예측 품질만 떨어집니다.
선택지
  • 배당률 캐시를 GCS 객체 하나로 공유 — 인스턴스 수·콜드스타트와 무관하게 하루 4회로 고정. 이미 쓰는 버킷이라 추가 비용은 사실상 0.
  • /predict만 비공개로 돌리고 대시보드는 공개 유지 — 쿼터는 지켜지지만 "직접 조합해 보는" 기능이 사라집니다.
  • 그대로 두고, 쿼터가 마르면 폼 모델로 떨어지는 걸 수용.

결정 2 · 예측 기록 DB가 꺼진 상태

정리 필요
현황
db.py는 죽은 코드가 아니라 실제로 호출되지만 연결이 안 되는 상태입니다. 서비스에 DATABASE_URL이 없어 시작할 때마다 database unavailable at startup을 남기고, 개별 /predict 요청은 기록되지 않습니다. 일별 배치 예측과 채점표는 GCS에 정상적으로 쌓입니다.
선택지
  • 현 상태 유지 + 코드에 "의도적으로 비활성"임을 명시 — 지금 필요한 기록은 GCS로 충분합니다.
  • db.py를 제거하고 GCS로 완전히 통일 — 더 정직하지만, 나중에 요청 단위 기록이 필요해지면 다시 만들어야 합니다.
  • Cloud SQL 연결 — 이 서비스에서 유일한 상시 과금 요소가 됩니다(최소 인스턴스도 무료 티어 없음).

결정 3 · 학습·서비스 입력 불일치를 어떻게 다룰지

품질
현황
모델은 북메이커 1곳 기준으로 배웠고, 서비스는 21곳 평균을 넣습니다. 어느 방향으로 얼마나 틀어지는지는 데이터 없이 단정할 수 없습니다.
선택지
  • 수용하고 채점표로 실측 추적 — 이미 채점 기능이 있습니다. 표본이 쌓이기 전에 구조를 바꾸면 원인 추적이 불가능해집니다.
  • 서빙을 단일 북메이커로 맞추기 — 과거 데이터와 같은 북메이커여야 의미가 있고, 그 한 곳이 값을 안 주면 예측이 빕니다.
  • 다중 북메이커 과거 데이터 확보 — 유료입니다.

결정 4 · 학습 데이터 갱신 주기

낮음
현황
재학습해도 항상 같은 9,727경기를 읽습니다(A표 2번 항목).
선택지
  • 시즌 종료 후 수동 갱신 — 캐시 파일을 지우고 재학습. 학습 자체가 수동 경로라 자동화 이득이 적습니다.
  • 캐시에 TTL 도입 — 재학습할 때마다 큰 CSV를 다시 받습니다.

결정 5 · 장애 알림이 없음

낮음
현황
runbook에 이미 적어둔 대로 자동 알림이 설정돼 있지 않습니다. 매일 도는 배치가 실패해도 사람이 대시보드를 열어봐야 압니다.
선택지
  • Uptime Check + 이메일 알림 — 무료 범위 안에서 됩니다. "배포해봤다"와 "운영해봤다"를 가르는 지점이기도 합니다.
  • 현 상태 수용 — 학습 목적이라면 합리적인 선택입니다.

결정 불필요, 인지만: /predict는 요청마다 football-data.org 시즌 캐시 갱신도 시도합니다(6시간 TTL). 이쪽은 무료 티어에 분당 제한이 있어 동시 요청이 몰리면 거부될 수 있지만, 실패하면 기존 캐시로 계속 서빙하도록 처리돼 있습니다. 또한 인스턴스 최대 3개·동시요청 80로 제한돼 있어 트래픽이 급증해도 비용이 무한히 늘지는 않습니다.

판단 근거는 모두 실제 데이터·로그·코드 확인에서 나왔습니다. 위 권고는 제 의견이고, 다르게 정하셔도 이유만 알려주시면 그대로 반영합니다.
